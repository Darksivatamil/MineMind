## Upgrade 27 — Combat Complete Rewrite: bot.pvp.attack() Removed, Dead-Simple Loop
Date: 2026-06-30

### ROOT CAUSE OF COMBAT NEVER WORKING
**`bot.pvp.attack()` internally calls `await this.stop()` which calls `pathfinder.stop()` then waits 5 seconds for a `path_stop` event. If the event never fires (which happens when pathfinder is mid-move from follow/explore), the promise REJECTS after 5 seconds — silently swallowed by my try-catch. Combat never starts.**

Every tick, `_protectTick()` called `bot.pvp.attack()`, it failed silently, and nothing happened. This was the TRUE reason combat has never worked across all 6+ attempted fixes.

### Complete Rewrite — What Changed

| Layer | Before | After |
|-------|--------|-------|
| Attack system | `bot.pvp.attack()` — 5s stop timeout, silent rejection | `bot.attack()` — direct, instant, no waiting |
| Target tracking | `_combatActive` boolean (vague) | `_combatTarget` entity ref (concrete) |
| Persistence | Called pvp.attack() fresh each tick | Loop: if target alive → attack/pathfind; if dead → clear |
| Abstraction | `_isHostileMob()` helper | Inline `hostileNames.some()` — 10 lines, no indirection |
| Guards | `_combatActive` checked in 4 places | `this._combatTarget` checked in 5 places after this fix |
| Logging | `[AGNES] protect: ...` — vague | `[FIGHT] Zombie spotted at 5.2m — attacking!` — crystal clear |

### New Combat Flow (Can't Fail)
```
Every _processTick() [800ms]:
  if _combatTarget is set:
    if entity still exists in bot.entities:
      if distance <= 4:  → bot.attack(target)
      if distance > 4:   → bot.pathfinder.setGoal(GoalNear)
    else:
      → clear target, log "[FIGHT] target dead/gone"
  else:
    scan bot.entities for mobs with hostile name
    if found:
      → set _combatTarget, equip weapon
      → attack or pathfind
      → log "[FIGHT] Zombie spotted at 5.2m — attacking!"
```

### All Pathfinder-Overriding Systems Now Guarded

- `_exploreTick()`: checks `this._combatTarget` → SKIPS during fight
- `_collectDrops()`: checks `this._combatTarget` → SKIPS during fight
- **Nothing can override combat pathfinding anymore.**

- Removed `_isHostileMob()` (was overengineered, inlined simple 10-line check)
